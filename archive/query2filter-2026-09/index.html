Abstract

Retrieval systems that turn a photo into a caption and then embed the caption text inherit a blind spot: whatever the caption schema leaves out becomes unsearchable, no matter how visible it is in the image. We ran into this directly while building a person-search feature — a fixed six-axis captioning schema (age impression, mood, toughness, urbanity, warmth, charisma) had no room for gender, age, glasses, or hats, so queries naming them failed outright.

The fix isn't obvious, because many everyday queries pack a hard filter and a description into one word — “granny” means both female-and-old and warm-and-familiar — so approaches that isolate a filter by deleting it from the query text are left with nothing. Query2Filter separates the two roles instead: a single LLM call extracts an explicit gender/age filter from any query and prunes the candidate pool, and a joint vision-language encoder (CLIP or SigLIP) ranks the pruned pool by comparing the raw query text directly to the images — no captioning schema involved in ranking at all.

Across two face datasets (CelebA and UTKFace) and two encoder backbones, this reaches a perfect top-10 demographic-match accuracy and clearly outperforms the schema-bound captioning approach on queries naming attributes the schema was never designed to hold. We also compare against a fine-tuned, domain-mismatched retrieval model (IRRA) and report the result honestly: Query2Filter wins on demographic accuracy, and IRRA — despite the domain gap — still edges it out on the harder attribute-ranking metric. We treat that as useful information, not something to explain away.

How Query2Filter works

Query2Filter runs in two steps. First, a single LLM call reads the raw query and returns an explicit filter — gender and age bracket, when the query actually implies them — plus whatever's left over. That filter prunes the candidate pool before anything else happens; if it prunes the pool to nothing, the weakest constraint relaxes first. Second, instead of ranking the pruned pool by matching a regenerated caption, Query2Filter embeds the raw query directly with an off-the-shelf joint vision-language encoder (CLIP or SigLIP) and compares it to image embeddings computed once, offline. No VLM captioning, no schema, no residual-generation call at ranking time.

That second step is a deliberate reversal. The system we built first ranked the pruned pool by regenerating a description in the same six-axis schema used to caption the corpus, then comparing that description's text embedding to the corpus captions. It looked reasonable until we tested it on queries naming an attribute the schema has no slot for — glasses, a hat, a mustache. The regenerated description simply omits the attribute, no matter how visible it is in the photo, and ranking by it performs little better than not filtering at all. Bypassing the schema and letting a joint embedding compare the query to the image directly removes that ceiling.

Results

Two evaluations matter here. The first is whether the extracted filter gets gender and age right — demographic accuracy. The second, harder one first restricts the candidate pool to the correct subgroup, so filter quality can't help or hurt, and then asks whether the ranking itself surfaces a specific named attribute — glasses, a hat — that the caption schema never represented.

This is where the schema-bound design collapses to barely above the no-filter baseline (0.478 vs. 0.489): regenerating a description in a schema with no slot for eyeglasses simply omits them, so ranking by that description is close to uninformative about that attribute. We also tried the obvious fix — adding a seventh, open-ended description axis for exactly this kind of attribute. It made things worse, not better (0.400), and we're reporting that as a negative result rather than quietly dropping the experiment.

Negative result

Broadening the schema doesn't rescue the schema-bound design — it makes the composite-query score worse (0.478 → 0.400). We read this as further evidence that the schema-bound approach was the wrong lever to keep pulling, not a tuning problem to solve.

Against a fine-tuned baseline (IRRA): we also compared Query2Filter to IRRA, a text-based person-retrieval model fine-tuned on a street-surveillance pedestrian dataset (CUHK-PEDES) and used here zero-shot, with no adaptation to our data. Despite that domain mismatch, IRRA is competitive — and on the harder attribute-ranking metric it actually edges out Query2Filter, while Query2Filter stays ahead on demographic accuracy. We think that two-sided result is more useful than only reporting the metric where we win.

Team

Castar Team

Castar started as a Capstone Design II team project with two tracks that grew out of the same problem: a casting-matching and AI actor-search product, and the retrieval research above, which came out of watching the product's own search fail on ordinary queries like “grandpa” or “schoolgirl.” The product track designs and builds the casting tools; the research track turned that specific failure into the Query2Filter study.
