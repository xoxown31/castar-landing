02 — RESEARCH

Query2Filter

NAACL Findings / ICLR 워크숍급을 목표로 진행 중인 연구입니다. 검색이 실패하는 지점을 정량적으로 진단하고, 그 위에 새 검색 방법을 설계했습니다.

진단 — 검색은 왜 실패했는가

Finding 01

Schema-Induced Capacity Ceiling

VLM으로 이미지를 캡션으로 바꾼 뒤 텍스트 임베딩으로 검색하는 "caption-then-embed" 구조는, 캡션 스키마에 없는 속성 — 예를 들어 성별, 안경 착용 여부 — 은 사진에 아무리 뚜렷해도 원천적으로 검색할 수 없습니다. 스키마가 곧 검색 가능한 속성의 상한선이 됩니다.

이미지지원자 사진
→
VLM 캡션스키마: 6축(나이인상 외)
→
텍스트 임베딩캡션 문장을 벡터화
→
검색 ✕성별 / 안경 착용 — 스키마 밖 → 검색 불가

Finding 02

Entangled Single-Token Queries

"할머니"라는 단어에는 필터(성별=여성, 연령대=노년)와 의미 내용이 한 토큰에 압축돼 있습니다. QAM 등 기존 span-deletion 기반 쿼리 분해 방법은 필터에 해당하는 span을 지우는 방식이라, 지울 대상이 단어 전체면 아무것도 남지 않아 원천적으로 처리하지 못합니다.

쿼리"할머니"
→
Span-Deletion (QAM 등)필터 span 삭제 → "" (공백, 붕괴) NG
쿼리"할머니"
→
Query2Filterfilter{성별:여성, 연령대:노년} + 의미 잔여 유지

방법 — Query2Filter

LLM이 쿼리에서 하드 필터(성별·나이)만 뽑아 후보군을 좁히고, 그 안에서의 랭킹은 CLIP/SigLIP 같은 joint vision-language 인코더로 원본 쿼리와 이미지를 직접 비교합니다.

쿼리자연어 그대로
→
LLM 하드 필터 추출성별 · 나이
→
후보군 축소필터 통과 후보만
→
CLIP / SigLIP원본 쿼리 ↔ 이미지 직접 비교
→
정렬된 결과랭킹 반환
처음엔 VLM 캡션을 재작성해 텍스트 임베딩으로 비교하는 "Ours-Doc" 방식을 먼저 시도했습니다. 스키마 밖 속성 쿼리에서 baseline 수준(0.478)으로 무너지는 걸 확인하고, CLIP/SigLIP로 원본 쿼리와 이미지를 직접 비교하는 방식으로 전환해 큰 폭으로 개선했습니다.
